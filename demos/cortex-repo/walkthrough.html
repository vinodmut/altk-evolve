Walkthrough · automated Docker demo

Evolve learns a repository's conventions

Run Claude Code on a small repository with rules it cannot guess, let Evolve learn from one recorded session with no grading or feedback, then compare fresh sessions with and without what it learned. Everything runs in one Docker container; nothing touches your own setup.

Two ways to run this. This page runs the scripted experiment in Docker: six graded pairs, a report. To wire Cortex and Evolve up yourself on your machine and watch each piece, follow the manual walkthrough.

What the experiment tests

The sample repository, shopkit, is a small Python library whose data model lives in schema/models.yaml. Its git hooks reject a commit unless it has:

  • regenerated code (make generate) and a database migration (make migration NAME=…),
  • an entry under ## Unreleased in CHANGES.md,
  • a bump of clients/python/VERSION whenever the client changes,
  • a Conventional Commit subject in lower case, such as feat(users): add nickname.

The task prompt says none of this. An agent finds out by reading .githooks/ or by having its commit rejected. The question is whether Evolve can learn those rules from one session's own rejections, so that later sessions avoid them.

For comparison, the author's run is recorded in reports/sonnet45-20261106/report.html: every baseline run was rejected twice; with Evolve, 2 of 6 runs committed first time and rejections fell from 12 to 7. Your numbers will differ; that is expected.

1

Check prerequisites

5 min
  • macOS or Linux with about 10 GB free disk.
  • Docker with Compose v2 and BuildKit, running. On a Mac, Docker Desktop or Colima (4 CPUs and 8 GB is enough).
  • Git.
  • API access to a Claude model, either an Anthropic API key or a gateway that serves the Anthropic Messages API. The same connection is used for Claude Code and for Evolve.
  • The two repositories, both public: vinodmut/altk-evolve on branch rossocortex (Evolve, this demo and the sample repository) and vinodmut/cortex on branch evolve-plugin (Cortex with the evolve plugin). Step 2 clones them.

Check Docker:

docker version --format '{{.Server.Version}}'
docker compose version
docker buildx version
✓

Expect three version lines. If the first one errors, Docker is not running: start Docker Desktop, or run colima start.

2

Get the code

2 min

Clone both repositories side by side into a fresh directory. This keeps the walkthrough separate from anything else on your machine.

export WALK="$HOME/cortex-evolve-walkthrough"
mkdir -p "$WALK" && cd "$WALK"
git clone --branch rossocortex https://github.com/vinodmut/altk-evolve.git evolve
git clone --branch evolve-plugin https://github.com/vinodmut/cortex.git cortex
cd evolve/demos/cortex-repo
ls
✓

Expect demo, driver.py, grade.py, shopkit/, tasks.json, walkthrough.html and others. Run every remaining command from this directory (…/evolve/demos/cortex-repo).

!

Keep the clone under your home directory. Colima only shares your home directory with Docker. A clone in /tmp builds but cannot store results.

3

Configure the model connection

3 min
cp ../cortex-photo/.env.example .env
chmod 600 .env
open -e .env   # or: nano .env

Fill in four values. The rest of the file is comments.

VariableAnthropic API directlyThrough a gateway
ANTHROPIC_BASE_URLhttps://api.anthropic.comyour gateway's URL
ANTHROPIC_API_KEYyour API keyyour gateway key
ANTHROPIC_MODELclaude-sonnet-4-6the gateway's Sonnet ID, e.g. aws/claude-sonnet-4-5
EVOLVE_MODEL_NAMEsame as ANTHROPIC_MODELsame as ANTHROPIC_MODEL

Leave EVOLVE_CUSTOM_LLM_PROVIDER=anthropic. Your own Claude Code login is never used; only this key.

!

Don't share .env. It holds your key. It is git-ignored and is mounted read-only into the container; it is never copied into the image or the results.

Then set three variables. Repeat this block in any new terminal before running ./demo:

export WALK="$HOME/cortex-evolve-walkthrough"
export CORTEX_CHECKOUT="$WALK/cortex"
export DEMO_RESULTS_DIR="$WALK/evolve/demos/cortex-repo/results-$(whoami)"
cd "$WALK/evolve/demos/cortex-repo"

CORTEX_CHECKOUT tells the build to compile Cortex from your clone. DEMO_RESULTS_DIR is where every session, guideline and report is written; a fresh name means a fresh experiment.

4

Build and start

10–15 min the first time
./demo setup

This builds the image (Go toolchain for Cortex, Python and uv for Evolve, Claude Code, the repository's tools, a small embedding model), starts Cortex, Evolve and a local bridge inside the container, and makes two small live API calls.

✓

Expect, at the end: 

{"claude": "live API OK", "evolve": "live API OK", "model": "…", "placement": "user"}

A line mentioning Provider List: https://docs.litellm.ai/… may appear above it; it is harmless.

!

If it fails with "Claude's live API check failed" or "structured-output API check failed", the URL, key or model ID in .env is wrong. Fix it and run ./demo setup again; a rebuild is quick after the first time.

5

Run the training session

about 3 min
./demo training

Claude Code starts in a fresh clone of shopkit and is asked to add an optional nickname field to users and commit it. It runs unattended (Bash, Read, Write and Edit are allowed; nothing else) and exits on its own. Cortex records every request and tool result.

✓

Expect one line, training: training session <uuid>, and then the prompt back after a few minutes. There is no progress output while Claude works.

See what happened. The training session normally hits at least one commit rejection; that rejection is what Evolve learns from:

cd "$DEMO_RESULTS_DIR/tasks/training" && git log --oneline && cd - >/dev/null
grep -o 'pre-commit: [^"\\]*\|commit-msg: [^"\\]*' "$DEMO_RESULTS_DIR/training-trajectory.json" | sort | uniq -c
✓

Expect two commits (the initial one and Claude's feat(…) commit) and a few rejection messages, such as pre-commit: schema/models.yaml changed without an entry in CHANGES.md.

!

If the second command prints nothing, Claude read the hooks and got the commit right first time. Evolve then has little to learn from. Note it, and continue anyway: it is a real outcome.

6

Let Evolve learn

1–2 min
./demo learn

Evolve reads only the recorded training session. Nobody tells it whether the session went well; it sees the commands, their output and the rejections.

✓

Expect three to six numbered candidates, for example: 

Candidate 2
When commit hooks reject a commit, read the error message to identify all
required companion changes (changelog, version bumps, commit format) before
re-attempting

The wording will differ from run to run.

7

Review and promote guidelines

5 min

Nothing learned is used until a person promotes it. Read each candidate and decide whether it is specific to what happened in the session and would help a different change in the same repository. Leave out generic advice ("be careful", "follow semantic versioning") and anything that names the training field (nickname).

Promote by ID, for example:

./demo promote 1 2 3 4
✓

Expect a JSON list of the promoted guidelines with their new IDs. This selection is now frozen for the experiment.

Write down which IDs you promoted and why you left any out. It is part of what to send back.

!

Running ./demo promote with no IDs promotes every candidate. Only do that deliberately.

8

Run baseline and guided sessions

about 45 min
./demo pairs --count 6

This runs 12 sessions, alternating: a baseline session gets no guidelines; a guided session gets the promoted guidelines, which Cortex puts in a <system-reminder> at the start of the first user message. Each pair adds the same new field (orders.discount_code, products.weight_grams or users.locale, rotating), and the arm that goes first alternates. Every session starts from a fresh clone.

✓

Expect one line per session as it starts, for example baseline-1: baseline session … then guided-1: guided session …, about 3–4 minutes apart.

Leave this terminal open. To watch progress from a second terminal (after repeating the variable block from step 3):

ls "$DEMO_RESULTS_DIR"/*-cli.json | wc -l    # 13 when done: training + 12 sessions
!

While it runs, do not run ./demo stop, ./demo setup or docker compose down in this directory: they stop the experiment. Other Docker work, and using Claude Code or Cortex normally on your machine, is fine; the container uses none of your ports or settings.

!

If it stops part-way (a network drop, a closed laptop), run ./demo pairs --count N again, where N is the number of pairs not yet finished (6 minus the finished ones). It completes any half-finished pair first, keeps the interrupted session's files as …-interrupted-1, and never overwrites a finished session.

9

Read the results

5 min
./demo report
open "$DEMO_RESULTS_DIR/summary.html"     # Linux: xdg-open

Grading happens in a separate container with networking disabled. It checks each committed repository: the change is committed, the pre-merge check and tests pass, the migration adds the column, a value round-trips through the library and the client, and the changelog, client version and commit subject are right.

✓

Expect two lines printed, one per arm, and a page with a table like:

BaselineWith Evolve
Correct and committed6/66/6
Commits accepted on the first try?/6?/6
Rejected commits (total)??

How to read it

  • Commits accepted on the first try and rejected commits are the main measures. The hooks force every run to fix its commit before finishing, so correctness is usually 6/6 in both arms.
  • The conventions table shows which rules caught each arm. In the author's run every baseline missed all three hook rules; guided runs missed them less often.
  • The Injected column should list your promoted IDs for every guided run and be empty for every baseline run. If not, the comparison is invalid; see troubleshooting.
  • Each run links to its full recorded trajectory, if you want to see exactly what Claude did.
10

Stop and clean up

1 min
./demo stop

This removes the container and its network. Your results stay in $DEMO_RESULTS_DIR. To remove everything later:

rm -rf "$HOME/cortex-evolve-walkthrough"
docker image rm cortex-invoice-runtime:local $(docker images --format '{{.Repository}}' | grep '^cortex-repo-') 2>/dev/null

Troubleshooting

SymptomCause and fix
Set CORTEX_CHECKOUT to a Cortex evolve-plugin checkoutThe variable block from step 3 was not run in this terminal. Run it, then retry.
Cannot connect to the Docker daemonDocker is not running. Start Docker Desktop, or colima start.
Build fails fetching from GitHub or PyPIThe build needs internet access. On a VPN or proxy, check Docker can reach github.com, proxy.golang.org and pypi.org.
Services are starting. Inspect ./demo logs.Setup has not finished, or a service crashed. Run ./demo logs; detailed logs are in $DEMO_RESULTS_DIR/runtime/ (cortex.log, evolve.log, bridge.log).
training already exists; evidence is not overwrittenThat step already ran in this results directory. To start over, run ./demo stop, pick a new DEMO_RESULTS_DIR, and ./demo setup.
A session ends very quickly; its *-cli.json shows an errorUsually an API limit or quota. Check $DEMO_RESULTS_DIR/<session>-cli.stderr.txt. Wait, then rerun ./demo pairs with the remaining count.
Promoted guidelines are not retrievableNothing was promoted, or promotion failed. Run ./demo candidates, then ./demo promote <ids>.
Guided runs show no injected IDs in the reportCortex did not apply the guidelines. Check $DEMO_RESULTS_DIR/runtime/cortex.log for evolve errors and send it back; don't draw conclusions from that run.
Learning returns no candidatesThe training session had nothing to learn from (no rejections). Keep the result; to retry, start a new results directory.

What to send back

Zip the results without the private runtime directory, which holds the CA key, Claude configuration and logs:

cd "$(dirname "$DEMO_RESULTS_DIR")"
zip -r "$(basename "$DEMO_RESULTS_DIR").zip" "$(basename "$DEMO_RESULTS_DIR")" -x "*/runtime/*"

Send the zip together with:

  • the model ID you used (ANTHROPIC_MODEL),
  • which candidate IDs you promoted and why you left any out,
  • anything that failed or surprised you, with the step number.

Never send .env or runtime/.
