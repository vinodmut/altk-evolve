Cortex + Evolve by hand

Run the self-improvement loop yourself, on your own machine: Cortex records your Claude Code sessions, Evolve learns guidelines from what went wrong, you promote the good ones, and Cortex injects them into the next session. No Docker, no driver, no grader.

How it fits together

Your everyday Cortex keeps running on its usual ports. You start a second, dev Cortex built with the evolve plugin on ports 477xx, plus Evolve's MCP server on port 8201. Only Claude Code runs you point at the dev Cortex take part.

Claude CodeA session in the sample repo--settings → :47700
Dev CortexRecords each turn; adds guidelines to the first user messageevolve plugin
EvolveAfter the session goes idle, writes candidate guidelinesMCP :8201
YouRead candidates and promote the useful onesevolve CLI
Next sessionGets the promoted guidelines injectedplacement: user
i

Two namespaces are the review gate. Learned guidelines land in cortex-candidates, which is never injected. Only what you copy to cortex is served. Session content includes tool output, so this stops an attacker's text from becoming a permanent instruction.

1

Prerequisites

5 min
  • Your everyday Cortex is installed and Claude Code trusts its CA (~/.cortex/ca/ca.crt exists). The dev Cortex reuses that CA and never writes to it.
  • Go 1.26.10 or later (go version) and uv (uv --version).
  • Claude Code (claude --version), logged in as you normally use it.
  • The two repositories, both public, on these branches (step 1 below clones them): vinodmut/altk-evolve on rossocortex (Evolve and the sample repository) and vinodmut/cortex on evolve-plugin (Cortex with the evolve plugin and its placement option).
  • A litellm proxy key that serves Claude Sonnet 4.6 (aws/claude-sonnet-4-6). Both Claude Code and Evolve use it, so the task model and the learner are the same model. Check with: curl -s -H "Authorization: Bearer $LITELLM_KEY" "$LITELLM_URL/v1/models" | jq -r '.data[].id' | grep sonnet (after setting the variables below).

Clone both repositories into one fresh directory:

export WALK="$HOME/tmp/cortex-evolve-manual"
mkdir -p "$WALK" && cd "$WALK"
git clone --branch rossocortex https://github.com/vinodmut/altk-evolve.git altk-evolve
git clone --branch evolve-plugin https://github.com/vinodmut/cortex.git cortex

Every terminal needs the same variables, so write them to one file, $WALK/env.sh, and source it in each terminal. Write it once:

umask 077
cat > "$WALK/env.sh" <<'EOF'
# Source this in every terminal: . "$HOME/tmp/cortex-evolve-manual/env.sh"
export WALK="$HOME/tmp/cortex-evolve-manual"
export CORTEX_SRC="$WALK/cortex"
export EVOLVE_SRC="$WALK/altk-evolve"
export PLAY="$WALK/playground"                     # everything this walkthrough writes
export LITELLM_URL="https://litellm.example.com"   # your litellm proxy URL
export LITELLM_KEY="replace-with-your-proxy-key"
export MODEL="aws/claude-sonnet-4-6"               # task model and learner; use your proxy's ID
# The sample repository's Python environment (created in step 6) comes first on PATH.
export PATH="$PLAY/shopkit-venv/bin:$PATH"
EOF
${EDITOR:-nano} "$WALK/env.sh"
!

Set LITELLM_URL and LITELLM_KEY in the editor before going on. The file holds your key, so it is written readable only by you; step 11 deletes it.

Now load it. Run this line in every new terminal before anything else in this walkthrough:

. "$HOME/tmp/cortex-evolve-manual/env.sh"
mkdir -p "$PLAY" && ls -d "$CORTEX_SRC" "$EVOLVE_SRC" "$PLAY" && echo "$LITELLM_URL · $MODEL"
✓

Expect three absolute paths, then your proxy URL and model. If a path is missing, check the clone step above.

i

The heredoc is quoted ('EOF'), so $HOME and $WALK are expanded each time the file is sourced, not when it is written. To change a value later, edit env.sh and source it again.

Build Cortex with the plugin

2 minterminal 3
i

From here on, each terminal's first command starts with . "$HOME/tmp/cortex-evolve-manual/env.sh". If you open another terminal, or restart one, run that line first.

. "$HOME/tmp/cortex-evolve-manual/env.sh"
cd "$CORTEX_SRC" && git log -1 --oneline && make cortex
✓

Expect include_plugin_evolve in the printed tag list, and a fresh $CORTEX_SRC/bin/cortex. Your installed Cortex in ~/.local/bin is unchanged.

!

If the tag is missing, you are on a branch without the plugin. Check out evolve-plugin.

Make sure the ports this walkthrough uses are free:

lsof -nP -iTCP:8201 -iTCP:47700 -iTCP:47701 -sTCP:LISTEN
✓

Expect no output. Your everyday Cortex uses 476xx and is not listed.

3

Start Evolve's MCP server

3 minterminal 1

Write Evolve's settings. This keeps all guidelines in $PLAY/data, separate from anything else in ~/.evolve:

. "$HOME/tmp/cortex-evolve-manual/env.sh"
umask 077
case "$PLAY" in /*) ;; *) echo "PLAY must be an absolute path; redo step 1's variables"; return 1 2>/dev/null || exit 1 ;; esac
cat > "$PLAY/evolve.env" <<EOF
EVOLVE_MODEL_NAME=litellm_proxy/$MODEL
LITELLM_PROXY_API_BASE=$LITELLM_URL
LITELLM_PROXY_API_KEY=$LITELLM_KEY
EVOLVE_BACKEND=filesystem
EVOLVE_DATA_DIR=$PLAY/data
EVOLVE_SQLITE_PATH=$PLAY/evolve.sqlite.db
EVOLVE_INJECTION_MODE=retrieval
EVOLVE_OTEL_ENABLED=false
EVOLVE_HOOKS_CONFIG=
EOF
!

The file is written with your shell's values, so check it: grep -E 'MODEL|BASE' $PLAY/evolve.env should show litellm_proxy/ followed by your $MODEL, and your proxy URL. EVOLVE_INJECTION_MODE=retrieval is required: without it Evolve matches the task text literally and returns almost nothing.

Start the server and leave it running:

set -a; . $PLAY/evolve.env; set +a
cd $PLAY && env -u HTTPS_PROXY -u HTTP_PROXY \
  uv run --project $EVOLVE_SRC evolve-mcp --transport sse --port 8201
✓

Expect, after a first-time download of a small embedding model:

INFO:     Uvicorn running on http://127.0.0.1:8201 (Press CTRL+C to quit)
i

env -u HTTPS_PROXY keeps Evolve's own LLM calls out of Cortex, so they don't show up as agent traffic.

Add a shortcut for the Evolve CLI in terminal 3. It reads the same data directory as the server:

ev() { (set -a; . $PLAY/evolve.env; set +a; cd $PLAY && env -u HTTPS_PROXY -u HTTP_PROXY uv run -q --project $EVOLVE_SRC evolve "$@"); }
ev namespaces create cortex
ev namespaces create cortex-candidates
4

Start a dev Cortex next to your everyday one

3 minterminal 2

Copy your installed config, move every listener from 4760x to 4770x, and add the plugin as the last outbound plugin:

. "$HOME/tmp/cortex-evolve-manual/env.sh"
sed -e 's/127.0.0.1:4760\([0-9]\)/127.0.0.1:4770\1/g' \
    -e 's/generate_ca: true/generate_ca: false/' \
    ~/.cortex/config.yaml > $PLAY/cortex.yaml
cat >> $PLAY/cortex.yaml <<'EOF'
      - name: evolve
        config:
          endpoint: http://127.0.0.1:8201/sse
          agents: [claude-code]
          placement: user
          idle_after_seconds: 90
          cache_ttl_seconds: 60
EOF
grep -c 4760 $PLAY/cortex.yaml
✓

Expect 0. The evolve entry must sit under pipeline: outbound: plugins:, indented like the plugin above it.

SettingWhy
placement: userGuidelines go in a <system-reminder> on the first user message. At the end of the system prompt the model ignored them (placement experiment).
idle_after_seconds: 90Send a session to Evolve 90 s after its last turn, instead of the default 15 minutes.
cache_ttl_seconds: 60A newly promoted guideline reaches running sessions within a minute.

Start it and leave it running:

env -u HTTPS_PROXY -u HTTP_PROXY $CORTEX_SRC/bin/cortex --config $PLAY/cortex.yaml
✓

Expect among the startup lines:

msg="session archive disabled — …" reason="not a local install"
msg="HTTP server listening" name=forward-proxy addr=127.0.0.1:47700

The archive is off because the config lives outside ~/.cortex, so nothing is written to your real session archive. Test runs do count toward today's cost in agentop.

Check the plugin is loaded, from terminal 3:

curl -s --noproxy '*' 127.0.0.1:47701/v1/pipeline | jq -c '[.outbound[] | {name, placement: .config.placement}]'
✓

Expect evolve last, with "placement":"user".

Finally, a settings file that routes Claude Code through the dev Cortex to the litellm proxy, on Sonnet 4.6. Your ~/.claude/settings.json pins HTTPS_PROXY to the everyday Cortex, and settings beat the shell environment, so --settings is the reliable override:

jq -n --arg url "$LITELLM_URL" --arg key "$LITELLM_KEY" --arg ca "$HOME/.cortex/ca/ca.crt" '{env: {
  HTTPS_PROXY: "http://127.0.0.1:47700", NODE_EXTRA_CA_CERTS: $ca,
  ANTHROPIC_BASE_URL: $url, ANTHROPIC_AUTH_TOKEN: $key}}' > $PLAY/claude-dev.json
chmod 600 $PLAY/claude-dev.json
dev-claude() { claude --settings $PLAY/claude-dev.json --model "$MODEL" "$@"; }
dev-claude -p "Reply with exactly: READY" --setting-sources ""
✓

Expect READY. Every dev-claude run now uses $MODEL through the proxy, whatever your normal Claude Code login or default model is.

!

An auth or "model not available" error means the key doesn't serve that model ID. List what it serves (prerequisites) and set MODEL to a Sonnet ID from that list, then rewrite this file and evolve.env.

5

Prove injection works with a canary

3 minterminal 3

Before learning anything, check that a promoted guideline actually reaches the model. Add one with a visible effect:

ev entities add cortex --no-conflict-resolution \
  -c "When you finish answering, end your reply with the exact line: EVOLVE-CANARY-7731" \
  -m '{"creation_mode":"manual","task_description":"any task in a scratch directory"}'
mkdir -p $PLAY/scratch && cd $PLAY/scratch && echo hello > a.txt
dev-claude -p "What files are in this directory?" --allowedTools "Bash(ls:*)" Read
✓

Expect the reply to end with EVOLVE-CANARY-7731.

See what the plugin recorded for that session:

S=$(curl -s --noproxy '*' 127.0.0.1:47701/v1/sessions | jq -r '.sessions | map(select(.agent)) | max_by(.createdAt) | .id')
curl -s --noproxy '*' 127.0.0.1:47701/v1/sessions/$S | jq -c '.events[] | select(.phase=="request" and .inference)
  | {seq, evolve: .plugins.evolve, why: [.invocations.outbound[]? | select(.plugin=="evolve") | .reason]}'
✓
{"seq":2,"evolve":{"injected":true,"ids":["1"],"cached":false,…},"why":["body_rewritten"]}

ids says exactly which guidelines shaped the request; cached: true on later turns means the block is reused, so prompt caching keeps working.

!

No canary? Read the why column against the troubleshooting table. No session at all usually means you ran plain claude instead of dev-claude.

Remove the canary before the real experiment. The scratch session is sent to Evolve once it goes idle; give it two minutes, then clear anything it produced so only the training session's lessons remain:

ev entities delete cortex 1
sleep 120
clear-candidates() {
  (set -a; . $PLAY/evolve.env; set +a; cd $PLAY && env -u HTTPS_PROXY uv run -q --project $EVOLVE_SRC python -c '
from altk_evolve.frontend.client.evolve_client import EvolveClient
c = EvolveClient()
for e in c.get_all_entities("cortex-candidates", filters={"type": "guideline"}, limit=1000):
    c.delete_entity_by_id("cortex-candidates", e.id); print("deleted candidate", e.id)')
}
clear-candidates          # usually prints nothing: the scratch session had nothing to learn
6

Set up the sample repository

3 minterminal 3

shopkit is a small Python/SQLite library whose git hooks reject any commit that lacks regenerated code and a migration, a CHANGES.md entry, a clients/python/VERSION bump, or a lower-case Conventional Commit subject. Nothing tells the agent this up front.

The repository's tools call python3 and need PyYAML and pytest. Give it its own environment so your system Python is untouched:

uv venv -q "$PLAY/shopkit-venv" && uv pip install -q --python "$PLAY/shopkit-venv/bin/python" pyyaml pytest
which python3     # env.sh already put this environment first on PATH
✓

Expect …/playground/shopkit-venv/bin/python3. If it shows a system Python, source env.sh again in this terminal.

Make a function that creates a fresh clone, with the hooks installed. You'll make one per session:

fresh() {
  rm -rf "$PLAY/$1" && cp -R $EVOLVE_SRC/demos/cortex-repo/shopkit "$PLAY/$1" && cd "$PLAY/$1" &&
  git init -q && git config core.hooksPath .githooks &&
  git add -A && git commit -q -m "chore: shopkit 0.4.0" && git log --oneline
}
fresh train
✓

Expect check passed: … from the hook, then one commit: … chore: shopkit 0.4.0. Run ./scripts/test to see 3 passed.

i

Claude's Bash tool inherits your PATH, so in any terminal that sourced env.sh, the repository's python3 finds its packages.

7

Run the training session

3–5 minterminal 3

Ask for a change and a commit. The flags keep your personal hooks, skills and memory out of the run, so it is reproducible:

cd $PLAY/train
dev-claude -p "In this repository, add an optional \`nickname\` field (text) to users. It should be stored and loaded like the other user fields and accepted by the Python client. Commit the change when it is ready to merge." \
  --setting-sources "" --strict-mcp-config --allowedTools Bash Read Write Edit --permission-mode acceptEdits
✓

Expect a summary after a few minutes. Then look at how the commit went:

git log --oneline
S=$(curl -s --noproxy '*' 127.0.0.1:47701/v1/sessions | jq -r '.sessions | map(select(.agent)) | max_by(.createdAt) | .id')
curl -s --noproxy '*' "127.0.0.1:47701/v1/sessions/$S?limit=2000" \
  | jq -r '[.events[].inference.toolResults[]? | select(.isError)] | unique_by(.toolUseId) | .[].content' \
  | grep -E 'pre-commit: |commit-msg: ' | sort | uniq -c
✓

Expect a feat(users): … commit, and one or two rejections such as:

   1 pre-commit: schema/models.yaml changed without an entry in CHANGES.md under '## Unreleased'
   1 pre-commit: clients/python/shopkit_client.py changed; bump clients/python/VERSION (minor for a new field)
   1 commit-msg: subject must be a Conventional Commit in lower case, e.g. 'feat(users): add nickname'

Those rejections are what Evolve will learn from. Nobody grades the session. (Each request carries earlier tool results again, so the command keeps one copy per tool call.)

!

No rejections? Claude read .githooks/ first and got it right. Evolve then has little to learn. Run fresh train2 and try again; it varies between runs.

8

Watch Evolve learn

2–3 minterminals 2 and 3
!

Do this before the session goes idle (within 90 s of the training run ending), or right after starting terminal 2. Evolve keeps only the first 40 and last 10 steps of a Cortex session by default, and a coding session runs 50–70 steps, so the rejections fall in the middle and get dropped. Raise the window on the plugin's processing profile:

ev processing-profiles get cortex | jq '.revision'          # note the revision, e.g. 1
cat > $PLAY/profile.json <<'EOF'
{"processors": [{"id": "guidelines", "plugin": "evolve.guidelines",
  "config": {"guidelines_mode": "standard", "trajectory_max_steps": 150}}]}
EOF
ev processing-profiles apply cortex --file $PLAY/profile.json --expected-revision 1
i

The plugin creates the cortex profile the first time it sends a session, so it exists once the canary session from step 5 has been sent. After that your edit is kept: the plugin's later refreshes only change values you haven't changed.

If get says the profile doesn't exist yet, don't create it yourself: the plugin would then reset it to its defaults. Wait until terminal 2 logs sent idle session to learn from for the canary session, then apply the edit.

About 90 seconds after the training session's last turn, terminal 2 logs the send:

msg="evolve: sent idle session to learn from" session=… messages=74 batch=…-1

Terminal 1 shows Evolve's LLM calls. A minute later, read what it learned:

ev entities list cortex-candidates --type guideline
ev entities show cortex-candidates 1          # replace 1 with each ID: content, rationale, trigger, source session
✓

Expect three to six candidates. From the recorded run, for example:

When commit hooks reject a commit, read the error message to identify all required
companion changes (changelog, version bumps, commit format) before re-attempting
!

Nothing after 3 minutes? Check terminal 2 for sending session to learn from failed (it retries every 30 s with the same batch) and terminal 1 for an LLM error. See troubleshooting.

9

Review and promote

5 minterminal 3

Promote a candidate only if it is grounded in what happened and would help a different change in the same repository. Leave out generic advice and anything naming the training field.

Promotion copies the text into the served namespace, keeping its provenance:

promote() {
  (set -a; . $PLAY/evolve.env; set +a; cd $PLAY && env -u HTTPS_PROXY uv run -q --project $EVOLVE_SRC python - "$@" <<'EOF'
import sys
from altk_evolve.frontend.client.evolve_client import EvolveClient
from altk_evolve.schema.core import Entity
client = EvolveClient()
for candidate_id in sys.argv[1:]:
    g = client.get_entity_by_id("cortex-candidates", candidate_id)
    keep = {k: g.metadata[k] for k in ("creation_mode", "agent_id", "session_id", "source_task_id", "task_description", "rationale") if k in g.metadata}
    [u] = client.update_entities("cortex", [Entity(type="guideline", content=g.content, metadata={**keep, "status": "active"})], enable_conflict_resolution=False)
    print(f"candidate {candidate_id} -> served as {u.id}: {g.content[:90]}")
EOF
  )
}
promote 1 2 3 4          # your chosen candidate IDs
ev entities list cortex --type guideline
i

Prefer pasting by hand? ev entities add cortex --no-conflict-resolution -c "<text>" does the same without provenance. To withdraw a guideline later: ev entities delete cortex <id>; it stops being injected within cache_ttl_seconds.

Compare a session with and without

15–20 minterminals 2 and 3

Use a different field from training, so you are testing transfer rather than recall. Run one session with injection off and one with it on, each in a fresh clone.

Baseline: injection off

Edit $PLAY/cortex.yaml and add inject: false under the evolve plugin's config:. Cortex hot-reloads the file; check it took:

curl -s --noproxy '*' 127.0.0.1:47701/v1/pipeline | jq '.outbound[] | select(.name=="evolve") | .config.inject'
fresh baseline
dev-claude -p "In this repository, add an optional \`discount_code\` field (text) to orders. It should be stored and loaded like the other order fields and accepted by the Python client. Commit the change when it is ready to merge." \
  --setting-sources "" --strict-mcp-config --allowedTools Bash Read Write Edit --permission-mode acceptEdits

Guided: injection on

Change it to inject: true (or remove the line), wait two seconds, then:

curl -s --noproxy '*' 127.0.0.1:47701/v1/pipeline | jq '.outbound[] | select(.name=="evolve") | .config.inject'
fresh guided
dev-claude -p "In this repository, add an optional \`discount_code\` field (text) to orders. It should be stored and loaded like the other order fields and accepted by the Python client. Commit the change when it is ready to merge." \
  --setting-sources "" --strict-mcp-config --allowedTools Bash Read Write Edit --permission-mode acceptEdits

Count rejected commits in each

rejections() {   # rejected commits in the newest session; pass an offset for older ones
  local S=$(curl -s --noproxy '*' 127.0.0.1:47701/v1/sessions | jq -r --argjson n "${1:-0}" '.sessions | map(select(.agent)) | sort_by(.createdAt) | reverse | .[$n].id')
  curl -s --noproxy '*' "127.0.0.1:47701/v1/sessions/$S?limit=2000" | jq -r '
    [.events[] | select(.phase=="request" and .inference)][0].plugins.evolve as $e
    | [.events[].inference.toolResults[]? | select(.isError and (.content | test("pre-commit: |commit-msg: "))) | .toolUseId] | unique | length
    | "session \("'$S'") · injected \($e.ids // [] | join(",") | if . == "" then "none" else . end) · rejected commits \(.)"'
}
rejections 1    # baseline
rejections 0    # guided
✓

Expect the baseline to show injected none and the guided run your promoted IDs. In the recorded six-pair run, every baseline had 2 rejected commits; guided runs had 0–2, and 2 of 6 committed first time.

!

One pair is an anecdote. Run variance is large. For a real comparison, repeat several pairs on products.weight_grams (integer grams) and users.locale (text), and alternate which arm goes first, or use the automated demo, which does this and grades each repository.

Inspect a guided session in the TUI: agentop observe -endpoint http://127.0.0.1:47701, then the detail pane of its first request shows plugins.evolve.

Clean up

1 min
rm -rf "$PLAY"      # config, guidelines, clones, the shopkit venv
rm -rf "$WALK"      # also the two checkouts and env.sh, which holds your key

Your everyday Cortex, its config, its archive and ~/.evolve were never modified. The only shared state is the cost ledger, where these runs remain as today's spend.

Troubleshooting

What you seeMeaning and fix
sending session to learn from failed … model '…' is not available for this API keyEvolve's key can't use its model. Check grep -E 'MODEL|KEY=' $PLAY/evolve.env shows litellm_proxy/$MODEL and your real key, not a placeholder. Restart terminal 1; the plugin retries the same batch every 30 s.
A variable is empty, or ev: command not foundThis terminal didn't source env.sh, or the helper was defined in another terminal. Run . "$HOME/tmp/cortex-evolve-manual/env.sh"; helpers such as ev and dev-claude are defined per terminal in the step that introduces them.
no such file or directory: ~/…/evolve.envPLAY holds a literal ~. Check env.sh uses $HOME, not ~, source it again, delete any stray ./~ directory, and redo step 3's cat command.
No session on :47701Claude went through your everyday Cortex. Use dev-claude (it passes --settings).
why: evolve_unavailableThe plugin couldn't reach Evolve. Check terminal 1 is up and endpoint ends in /sse; terminal 2 logs the error. It retries after 60 s.
why: no_guidelinesEvolve returned nothing. Check EVOLVE_INJECTION_MODE=retrieval was set when terminal 1 started, and ev entities list cortex isn't empty.
why: no_toolsA tool-less side call (title, summary). Skipped on purpose.
unknown field "placement" in terminal 2Cortex is older than ab08dda3. Pull evolve-plugin and rebuild (step 2).
No "sent idle session" lineThe session had fewer than 2 successful turns, or isn't idle yet. Wait idle_after_seconds plus up to 30 s.
Learning fails with a schema or JSON errorYour learner model doesn't support Evolve's structured output. Use a model that supports forced tool calls (litellm_proxy/aws/claude-sonnet-4-6 does), restart terminal 1; the plugin resends the same batch.
Candidates say nothing about the hooksThe window was not raised before learning (step 8), so the rejections were dropped. Run a new training session.
ModuleNotFoundError: yaml in Claude's outputThe terminal didn't source env.sh, so the shopkit environment isn't on PATH. Source it and rerun in a fresh clone.
Turns lost after restarting CortexUnsent turns are held in memory. Let a session go idle and be sent before restarting.
