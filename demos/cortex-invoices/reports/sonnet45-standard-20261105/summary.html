Invoice extraction with standard guidelines

Correct packets: 3/3 baseline → 3/3 guided. Tool calls: [18, 15, 17] → [17, 17, 19]. Total: 50 → 53. Median: 17 → 17; range width: 3 → 2.

This is the first standard-guideline Sonnet invoice experiment. Earlier Sonnet invoice guides were generated with fast or accurate consistency methods.

Every baseline and guided packet passed: all 16 complete item rows and all three monetary reconciliations. Tool calls totaled 50 baseline versus 53 guided, a 6% increase. Both medians were 17. Standard guidelines did not improve correctness or reduce calls in this set.

Call-count range width narrowed from 3 to 2, but three exploratory observations do not establish improved reliability. Recorded tool errors totaled nine in each arm.

All three guided runs tried three incorrect /tmp PDF paths before checking pwd, despite the absolute-path guideline. Baselines 1 and 2 made the same path errors; baseline 3 used a different route and recovered from two script/edit errors.

All six runs included Decimal in their extraction/reconciliation commands. The arithmetic guideline reinforced behavior already present in the baselines. These two procedural themes also appeared in earlier fast-consistency advice; the generated standard wording is preserved unchanged.

Standard learning generated four candidates. Two reusable candidates were promoted unchanged before evaluation; blanket advice against parsing/OCR and dynamic data handling was rejected. The full selection rationale is linked below.

The learning log records two LiteLLM completion invocations. Standard mode performed no decision resampling and produced no analyzer scores. Learning-token usage and cost were not separately captured.

Task and Evolve models: aws/claude-sonnet-4-5 and aws/claude-sonnet-4-5. Claude Code 2.1.287, Cortex, Evolve, Poppler and Tesseract run inside Docker; inference uses the remote API.

Architecture

Task

Three invoices, five PDF pages, 16 items: text extraction, repeated table headings, a description continuing across a page boundary, an image-only second page, signed credits, a three-decimal price and a deliberately mismatched printed total. Every pair and repetition receives the same trial-1 PDF bytes and task text.

Extract every invoice line item from the PDFs in input/ into items.csv.
Use exactly these columns: invoice_id,vendor,description,quantity,unit_price,line_amount.
Preserve invoice IDs and complete item descriptions, including continuation text.
Include credits and discounts as signed line items. Do not include table headings,
page subtotals, tax, or grand totals as items. Preserve exact decimal amounts.

Reconcile each invoice's sum of line amounts plus its printed tax against its
printed total. Write reconciliation.csv with exactly these columns:
invoice_id,subtotal,tax,printed_total,computed_total,difference,status.
Difference means computed_total minus printed_total. Status must be matched
when the difference is zero and discrepancy otherwise. Report any discrepancy.

Keep all source PDFs unchanged. Use the installed local tools; do not install
packages or write persistent memory files. If using Python, run it with
uv run --offline --no-sync --project /opt/demo python.
Show the successful commands and briefly explain how you checked the result.

Learning and isolation

Evolve's standard generator reflects on the original byte-identical, verified training trajectory and its tool calls/results. It does not resample decisions or compute consistency uncertainty. No evaluation recording or feedback is used for learning. Selection is frozen before six fresh batch sessions, ordered baseline/guided, guided/baseline, baseline/guided. Each has a fresh UUID, workspace and Claude configuration. Bash, Read, Write and Edit are permitted with no stdin or interactive permission prompts.

Cortex recordings lack PDF image bytes and hidden reasoning. The learner therefore sees parsed text and recorded tool interactions rather than the complete visual context. Fresh CSV grading establishes correctness. All tasks share a container/results volume, so filesystem permissions do not isolate sibling workspaces. The author-side oracle is absent from the task container.
